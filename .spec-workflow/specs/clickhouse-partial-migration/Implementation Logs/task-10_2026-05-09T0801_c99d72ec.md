#### Integration
- **Description:** Cloudflare Tunnel routing separates Hono analytics API from existing PostgREST routes, keeping /api/analytics/* on Hono and /collection_count_view plus /rpc/* on PostgREST.
- **Frontend Component:** Vercel frontend using VITE_COLLECTION_COUNT_ENDPOINT only after approved cutover.
- **Backend Endpoint:** Cloudflare route /api/analytics/* -> Hono 127.0.0.1:8787; /collection_count_view and /rpc/* -> PostgREST 127.0.0.1:3000
- **Data Flow:** Browser request -> Cloudflare Tunnel path routing -> Hono or PostgREST -> ClickHouse snapshot or fallback response.

#### Integration
- **Description:** No-Docker VPS deployment uses monorepo-root systemd units for API and scheduled tools, with /srv/AtpDashboard as WorkingDirectory and /etc/atpdashboard env files.
- **Frontend Component:** None
- **Backend Endpoint:** AtpDashboardAnalyticsApi.service exposes Hono locally for Cloudflare Tunnel.
- **Data Flow:** systemd service starts pnpm --filter @atpdashboard/api start -> Cloudflare Tunnel proxies /api/analytics/* -> systemd timers run pnpm workspace scripts for sync/refresh/compare.

#### Integration
- **Description:** Incident and rollback flow uses FORCE_COLLECTION_COUNT_FALLBACK=true, Hono service restart, optional Cloudflare route revert, and compare validation before fallback is disabled.
- **Frontend Component:** Frontend endpoint can be reverted to PostgREST by unsetting or changing VITE_COLLECTION_COUNT_ENDPOINT.
- **Backend Endpoint:** GET /api/analytics/status and GET /api/analytics/collection_count_view
- **Data Flow:** Incident detected -> force fallback/env restart -> verify headers/status -> repair sync/refresh -> run clickhouse-only compare -> owner approves fallback off.
